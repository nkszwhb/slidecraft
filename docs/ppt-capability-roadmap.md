# PPT 能力扩展方案：把首页变成“演示策略台”

日期：2026-10-25

## 1. 本轮已落地

### 动效系统

- 首页新增动画设置：
  - 动画风格：无动画、克制、活力、电影感
  - 页面切换：无、淡入、推入、擦除
  - 元素出场：整组出现、逐项出现
- 大纲阶段支持逐页编辑动效：
  - 目标元素：标题、正文、要点、图片、图表
  - 效果：淡入、上浮飞入、缩放、擦除、直接出现
  - 整组或逐项出场
- AI 会结合用户自然语言和首页偏好，为每一页生成 0–4 条动效规则。
- 动效采用受限语义协议，不允许 AI 直接生成任意 OOXML。
- OfficeCLI 将动效写为 PowerPoint 原生动画，可在 PowerPoint 的“动画窗格”里继续编辑。
- 网页全屏演示同步支持元素入场动效。
- 当 OfficeCLI 不可用时，PPTX 仍会正常输出，只是不包含原生动画，并在任务日志中明确提示。

示例用户提示：

> 第 1 页标题淡入，第 3 页四个步骤逐项飞入；全篇使用克制的页面切换，不要夸张动画。

AI 会把这类自然语言落到具体页和元素目标上，而不是做字符串匹配。

### 其他已落地设置

- 内容密度：精简、标准、详细。
- 页码开关。
- 页脚品牌开关。
- 这些设置和动画偏好一起保存在任务快照中，后续修改不会改变已生成文件。

### 高级

## 4. AI 动效控制协议

### 原则

1. AI 只选择语义目标和受支持效果，不生成原始 XML。
2. 用户显式指令优先于全局偏好；全局偏好优先于 AI 自由发挥。
3. 动效数量有上限，默认每页不超过 4 条。
4. 页脚、页码、背景装饰永不参与动画。
5. 生成后进行结构验证，失败时交付无动画版本而不是损坏文件。

### 数据模型

```json
{
  "motion": {
    "style": "dynamic",
    "transition": "fade",
    "elementSequence": "sequence"
  },
  "slides": [
    {
      "layoutId": "process",
      "animations": [
        {
          "targets": ["title"],
          "effect": "fade",
          "durationMs": 500,
          "delayMs": 0,
          "trigger": "click",
          "sequence": "group"
        },
        {
          "targets": ["items"],
          "effect": "fly",
          "direction": "up",
          "durationMs": 450,
          "delayMs": 100,
          "trigger": "after",
          "sequence": "sequence"
        }
      ]
    }
  ]
}
```

### 映射链

```text
用户自然语言 + 首页设置
→ AI 输出语义动画规则
→ Schema 校验
→ 渲染器为语义元素写入 objectName
→ OfficeCLI 按 shape id 写 PowerPoint timing
→ OfficeCLI 验证
→ PowerPoint 动画窗格可继续编辑
```

## 6. 成功指标

- 首次生成后，用户无需重新制作动画的比例。
- 动画任务中，用户手动修改动效的页数占比。
- 生成后 24 小时内下载 PPTX 的比例。
- PowerPoint 打开成功率与修复提示率。
- 从任务创建到确认大纲的完成率。
- 动效相关任务的平均生成时长和 OfficeCLI 失败率。

## 7. 关键风险

- **兼容性**：只写 PowerPoint 支持的 OOXML，必须有真实 PowerPoint 打开回归。
- **过度动画**：默认“克制”，并限制每页数量和时长。
- **模型不稳定**：语义 Schema + 服务端兜底动效，不依赖模型每次都正确。
- **性能**：OfficeCLI 动画写入必须批量执行，避免逐元素多次启动。
- **可选依赖**：OfficeCLI 缺失时保持 PPTX 可交付，动画降级为网页预览。
